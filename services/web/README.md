# SAMoparser Web — фронтенд локального MVP

Клиентское приложение системы учёта и комплаенса ПО для кейса ПУ «СургутАСУнефть».
Реализовано на технологиях, зафиксированных в `package.json` репозитория: **React 19 + Vite 6 + react-router-dom 6 + lucide-react**. Новых зависимостей не добавлено; графики, таблицы, модальные окна и дизайн-система сделаны на CSS/SVG без внешних CDN.

## Запуск

### В составе Docker Compose (основной путь)

```bash
./scripts/dev.sh env
./scripts/dev.sh up      # PostgreSQL, Redis, migrate, api:8000, ingest:8001, web:8080
open http://localhost:8080
```

`nginx.conf` проксирует относительные `/api/...` на `api:8000` и `/ingest/...` на `ingest:8001` без обрезки префикса. Сборка образа: `npm run build` внутри `services/web/Dockerfile`.

### Локальная разработка (Vite)

```bash
cd services/web
npm install
npm run dev            # http://localhost:5173
```

Vite проксирует `/api`, `/ingest`, `/health`, `/ready`, `/metrics` на backend (`http://127.0.0.1:8000` и `:8001` по умолчанию). Цели переопределяются переменными `VITE_PROXY_TARGET` и `VITE_INGEST_PROXY_TARGET`; базовый путь API — `VITE_API_BASE_URL` (по умолчанию `/api/v1`). `server.host = 0.0.0.0` и `allowedHosts` включены для работы через внешний preview-прокси.

```bash
npm run build          # production-сборка в dist/
npm run preview        # предпросмотр сборки с теми же proxy-правилами
npm test               # node:test для локального матчера
```

## Контракт с backend

Клиент работает **только с публичным REST API** `services/backend/app/api.py` (`/api/v1/...`), не обращается к БД и не вызывает AI-провайдеров. `src/api/client.js` содержит все используемые ручки:

| Экран | Вызовы |
|---|---|
| Обзор | `GET /dashboard/summary`, `GET /risks`, `GET /catalog`, `GET /installations` (все страницы) |
| Комплаенс-контроль | `GET /catalog`, `GET /installations` → баланс «доступно мест vs уникальные ПК» |
| Каталог ПО | `GET/POST /catalog`, `DELETE /catalog/{name}` |
| Лицензии и квоты | `GET /catalog`, `POST /catalog` (upsert `license_count`) |
| Компьютеры | `GET/POST /devices`, `DELETE /devices/{computer_id}` |
| Установки | `GET /installations?status&limit&offset`, `POST /installations`, `DELETE /installations/{id}`, `POST /review` |
| Импорт данных | `POST /import/installations` (multipart: `.csv`/`.json`/`.xlsx`, `Idempotency-Key`) |
| Риски | `GET /risks` |
| Проверка имён | `GET /installations`, `GET /catalog`, `POST /review` |
| ИИ-лаборатория, ассистент | локальные данные из тех же ручек, без сетевых AI-вызовов |

`src/app/AppDataContext.jsx` один раз загружает справочники, сводку и риски, а полный срез установок читает страницами по 500 записей (ограничение 100 страниц, параллелизм 4) с индикатором прогресса. После любой мутации вызывается общий `refresh()`.

Обработка ошибок единая: `ApiError` разбирает формат FastAPI (`detail` может быть строкой или объектом со списком `computer_ids`), все экраны имеют состояния `loading / empty / error + retry`, уведомления — через `ToastProvider`, индикатор доступности API — в шапке.

### Минимальное изменение контракта backend

Для ручного удаления факта установки (обязательное требование ТЗ) в ответ `installation_view` добавлены аддитивные поля `id` и `observed_at`. Существующие ключи и тесты не изменены; проверка — `tests/test_web_api_contract.py`.

## Экраны и соответствие ТЗ

| Раздел | Что закрывает |
|---|---|
| **Обзор** | KPI, качество сопоставления, структура рисков, топ нарушений и баланс |
| **Комплаенс-контроль** | Ключевой экран MVP: «Куплено лицензий vs Установлено по факту», подсветка «Штрафной риск: … установлен на N ПК при M местах», дедупликация инсталляций по `computer_id`, выгрузка CSV |
| **Каталог ПО** | Просмотр и ручное ведение: типы лицензий (`free` / `paid` / `conditional_free`), статусы политики (`current` / `outdated` / `prohibited`), количество мест |
| **Лицензии и квоты** | Редактирование доступных мест, остатки и дефициты; явно помечено, что реестра договоров в API нет |
| **Компьютеры** | База устройств и закреплённых сотрудников/подразделений, регистрация перед импортом |
| **Установки** | Пагинация, фильтр статуса, ручное добавление/удаление, human-in-the-loop сопоставление |
| **Импорт данных** | «Коннектор» CSV/JSON/XLSX, шаблон файла, `Idempotency-Key`, отчёт `accepted/unknown/replayed`, понятная ошибка 422 |
| **Риски** | Группировка срабатываний, фильтры по критичности и классу, рекомендации |
| **Проверка имён** | Очередь «грязных» имён и подтверждение канонического продукта через `/review` |
| **ИИ-лаборатория / ассистент** | Бонусные кейсы А (Smart Matching), Б (EULA), В (чат) в честном офлайн-исполнении |

## Границы честности (ADR-0001, docs/implementation-plan.md)

- Excel кейса **не является реестром закупок**: нет цен, сроков, метрик и подтверждённых количеств. Поле `license_count` — legacy-справочник; `null` означает «неизвестно», а не «0». Поэтому денежная оценка штрафного риска, «зомби-софт» и юридические выводы в UI не выдаются за факты.
- Внешний LLM, pgvector, text-to-SQL, chat/EULA-endpoint’ы и `/ingest/v1/*` в backend прототипе не реализованы. Вместо них — локальные детерминированные эвристики (`src/lib/matching.js`, `src/lib/eula.js`, `src/lib/assistant.js`), которые явно помечены как рекомендации, ничего не отправляют наружу и требуют подтверждения человеком.
- Ассистент не выполняет SQL: ответы строятся по данным, уже полученным через публичное API.
- Журнал загрузок на экране «Импорт» — локальный список текущей сессии браузера, а не серверный `ingest_batches`.

## Структура

```
src/
├── api/client.js             # REST-клиент, ApiError, все ручки API
├── app/AppDataContext.jsx    # загрузка/кэш данных, постраничный срез, refresh
├── app/useMutation.js        # мутации + toast + обновление данных
├── components/
│   ├── Layout.jsx            # sidebar, topbar, навигация, статус API
│   ├── Assistant.jsx         # плавающий офлайн-ассистент
│   └── ui.jsx                # дизайн-система: карточки, таблицы, модалки, графики
├── lib/
│   ├── analytics.js          # баланс, дедупликация ПК, очередь проверки, риски
│   ├── matching.js           # офлайн Smart Matching (+ node:test)
│   ├── eula.js               # эвристический разбор EULA
│   ├── assistant.js          # локальные ответы на вопросы
│   ├── format.js             # подписи и форматирование
│   └── download.js           # клиентский экспорт CSV (UTF-8 BOM)
└── pages/                    # 10 экранов приложения
```
